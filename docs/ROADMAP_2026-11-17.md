# Roadmap: the eight open weaknesses (2026-11-17)

Baseline: the A2 P-coder with wide I-frames is +39.9% vs x264 (4:2:0 anchor, 256x256 DAVIS
TEST, GOP 30). Each item below is a test with a gate fixed before it runs. Some may fail;
a failed gate closes that line and the next item goes ahead.

| # | Weakness | Work | Needs | Rough time | Order |
|---|---|---|---|---|---|
| 0 | Measurement: 4:2:0 anchor, narrow overlap, 256x256 | 4:4:4 and CRF 8-18 anchors; UVG 1080p | CPU, then GPU | 1 day | running |
| 1 | We still lose to x264 | The sum of the items below | | | |
| 2 | cows and schoolgirls far behind | Lower-rate models (lambda 3e-3, 1e-2); encode tuning | GPU training | 1-2 days | 3 |
| 3 | No B-frames | Oracle first: the P-coder with a two-sided reference. Then train a B-coder | GPU training | 3-5 days | 4 |
| 4 | Slow | Profile; batch the range coder; mixed precision | CPU | 1-2 days | 2 |
| 5 | Simple motion search | Wider range and a hierarchical search at 1080p; sub-pixel motion | CPU and GPU | 2 days | 5 |
| 6 | MS-SSIM barely improved | A fine-tune with an MS-SSIM loss, reported as a second model set | GPU training | 1-2 days | 6 |
| 7 | Few test sets | UVG (running), then MCL-JCV; HEVC Class B needs a licensed copy | download | 1 day | with 0 |
| 8 | Audit was one pass | A second audit of the entropy coder, the container and the docs | none | 1 day | last |

Encode-time tuning (`docs/PLAN_encode_tuning.md`) is already running and feeds items 1 and 2.

## Rules

- Every gate is written down before its run, and both passes and failures are reported.
- Settings are picked on VAL-B. TEST and UVG are only for final numbers.
- Item 1 is the goal, not a task. It is met only when a real-bytes, decode-exact run beats
  x264 on the stricter anchor.
